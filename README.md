# 日本株スクリーニング — データ取得スクリプト

`daily-stock-screening-ai.md` の **Role 2（一次スクリーニング）を自動化**するスクリプトです。
出力されたCSVをチャットに貼れば、Role 0〜7 の分析に進めます。

> **免責**：本スクリプトは分析作業を補助するツールです。投資助言ではありません。
> 売買の判断と結果責任はすべて利用者にあります。

---

## この検証プロジェクトの原則（AIアシスタントは必ず守ること）

利用者の明確な方針です。今後この方針に沿って進めること。別セッションのAIも
最初にここを読んで従うこと。

1. **事実にもとづいて決める。勝手な想定で決めない。**
   - データ・API仕様・計算結果など、確認できる事実だけを根拠にする。
   - 列名・データの中身・プラン内容などを推測で決め打ちしない。
     不明なら、実データを表示・確認してから実装する。
   - 「たぶんこうだろう」で進めて、あとで手戻りさせない。

2. **一度出した助言や結論を、根拠なく変えない。**
   - 意見を変えるときは、それを裏づける新しいデータ・事実を必ず示す。
   - 予想と違う結果が出たら、予想が外れたことを認める。事実を曲げない。

3. **検証の作法を守る（過剰最適化・偽陽性を避ける）。**
   - 条件は一度に1つずつ足す。網羅探索の最良は分割検証で本物か確認する。
   - 先読み（look-ahead）を作り込まない。対相場超過で市場と比較する。
   - 手数料・スリッページ未考慮であることを常に明記する。

4. **不確実なことは、不確実なままに伝える。**
   - LLMの文章生成・主観評価で数値や判定を作らない（ハルシネーション排除）。
   - 判定はAPI由来の数値と計算のみ。計算式・閾値・出典を明示する。

## 使うデータ源（どちらも公式API）

| API | 提供元 | 費用 | 用途 |
|---|---|---|---|
| J-Quants API V2 | JPX総研（公式） | Freeプランあり※ | 株価・決算サマリー・銘柄一覧 |
| EDINET API v2 | 金融庁（公式） | **無料** | 大量保有報告書（バックテストでは不要） |

※ Freeプランはデータが**12週間遅延**します。検証には十分ですが、当日売買には使えません。
本番運用に移る際は有料プランへ切り替えてください。

規約でスクレイピングを禁止しているサイト（Yahoo!ファイナンス等）は一切使っていません。

## セットアップ（所要 15〜20分）

### 1. APIキーを取得する

**J-Quants**
1. https://jpx-jquants.com/ でアカウント登録
2. **プラン選択まで完了させる**（Freeプランでも、選択しないとAPIが有効になりません）
3. ダッシュボード → API Keys でキーを発行

**EDINET（バックテスト段階では不要）**
1. https://api.edinet-fsa.go.jp/ （EDINET API の登録ページ）でメールアドレスを登録
2. APIキーが無料で発行されます

> **検証だけならJ-Quantsの登録だけで足ります。**
> EDINETの大量保有報告書はRole 5（週次の深掘り）で使うもので、
> バックテストには使いません。

### 2. Pythonの準備

```bash
# フォルダに移動
cd stock_screener

# 依存ライブラリをインストール
pip install -r requirements.txt
```

### 3. APIキーを環境変数に設定

**Mac / Linux**
```bash
export JQUANTS_API_KEY="発行したキー"
export EDINET_API_KEY="発行したキー"
```

**Windows（PowerShell）**
```powershell
$env:JQUANTS_API_KEY="発行したキー"
$env:EDINET_API_KEY="発行したキー"
```

毎回打つのが面倒なら `.env.example` を `.env` にコピーして書き込み、
`python-dotenv` を使う形にもできます。

## 使い方

### ステップ1：まず `inspect` を実行してください（重要）

```bash
python main.py inspect
```

APIが返す**実際の列名**を表示します。
J-Quantsは2025年12月のV2移行で列名が変わっており、今後も変わる可能性があります。
表示された列名が `sources.py` の候補リストに無い場合、そのままだとエラーになります。

**出力結果をそのままチャットに貼っていただければ、こちらで修正します。**

### ステップ2：バックテストで検証する（★Freeプランはここから）

```bash
python main.py backtest
```

過去2年分のデータを取得し、1か月ごとに時点を巻き戻してスクリーニングを実行、
その3か月後にどうなったかを集計します。数分かかります。

**先読み（look-ahead bias）の防止**

バックテストで最も壊れやすい部分です。以下を徹底しています。

1. 株価は `date <= 検証時点` のみ使用
2. 決算は**開示日**で切る（決算期末で切ると、まだ発表されていない数字を使ってしまいます）
3. 移動平均・52週高値はすべて後方参照のみ

`python test_backtest.py` を実行すると、ランダムな値動きの合成データで検証できます。
**ランダムデータで超過リターンがほぼゼロになる**ことが、先読みが起きていない証拠です。

**出力される指標**

```
--- 3か月後リターン（単純保有した場合） ---
--- 期間中の最大上昇率（+50% / +100% / +200%到達率）---
--- Role 7 の執行ルールを適用した場合 ---
--- 相場全体との比較 ← 最重要 ---
```

**「相場全体との比較」が最も重要です。** 抽出銘柄が+30%でも、
同じ期間に市場全体が+35%なら、その戦略には価値がありません。

### ステップ3：スクリーニング実行（有料プランに切り替えた後）

```bash
python main.py run
```

出力：
```
output/YYYY-MM-DD_candidates.csv   通過銘柄（Excel等で開ける）
output/YYYY-MM-DD_paste.md         チャットに貼り付ける用
```

実行すると、絞り込みの経過が段階ごとに表示されます。

```
株価×決算の突合後: 3812銘柄
株価 200円以上: 3812 → 3450
時価総額 30〜500億円: 3450 → 2103
売買代金 3.0億円以上: 2103 → 287
営業利益YoY +30%以上 or 黒字転換: 287 → 41
売上YoY +15%以上: 41 → 12
除外業種を除く: 12 → 11
```

**どの条件で何銘柄落ちたかが見える**のが重要です。
1つの条件だけで9割落ちているなら、その条件が実質的に全てを決めています。

### ステップ4：結果をチャットへ

`output/YYYY-MM-DD_paste.md` の中身をコピーして、
`daily-stock-screening-ai.md` の実行コマンドと一緒に貼り付けてください。

## 条件の調整

`config.py` の数値を変更します。

```python
MAX_MARKET_CAP     = 50_000_000_000   # 時価総額の上限 500億円
MIN_TURNOVER_VALUE = 300_000_000      # 売買代金の下限 3億円
MIN_OP_PROFIT_YOY  = 0.30             # 営業利益YoY +30%
MIN_SALES_YOY      = 0.15             # 売上YoY +15%
```

**検証中は一度に1つだけ変更してください。**
複数を同時に変えると、どの変更が効いたのかわからなくなります。

候補が0件の日が続く場合、まず緩めるべきは `MIN_SALES_YOY` です。
売上の伸びは利益より遅れて出るため、ここが最も多く落とします。

## 毎日自動で動かす（任意）

`.github/workflows/daily.yml` を使うと、GitHub Actions で毎営業日17:30に自動実行できます。
パソコンを起動していなくても動きます。

1. このフォルダをGitHubの**プライベートリポジトリ**にpush
2. リポジトリの Settings → Secrets and variables → Actions で以下を登録
   - `JQUANTS_API_KEY`
   - `EDINET_API_KEY`
3. Actions タブから動作を確認

結果は Actions の実行結果ページから artifact としてダウンロードできます。

> APIキーは**絶対にコードに直接書かないでください。** 必ずSecretsを使ってください。
> パブリックリポジトリにキーが載ると、第三者に使われます。

## 前年同期比の計算方法について

決算サマリーの売上・営業利益は「累計」で開示されます（1Q、2Q累計、3Q累計、通期）。
そのため単純に前回開示と比べると期間がズレます。

このスクリプトは **同じ期種どうしを1年前と比較** しています。

- 今回が「2Q累計」なら → 前年の「2Q累計」と比較

期間が揃うため、四半期を切り出す処理をせずに正しいYoYが出せます。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| `JQUANTS_API_KEY が設定されていません` | 環境変数の設定を確認。ターミナルを閉じるとリセットされます |
| `必須の列が見つかりませんでした` | `python main.py inspect` の出力をチャットに貼ってください |
| 株価が0件 | Freeプランは12週間遅延。`config.PRICE_LOOKBACK_DAYS` を大きくしてください |
| `429 Too Many Requests` | レート制限です。数分待ってから再実行してください |
| 通過0銘柄 | **正常な結果です。** 無理に条件を緩めず、数日分の推移を見てください |
| バックテストが遅い | 2年分×4000銘柄で数分かかります。`BACKTEST_STEP_DAYS` を大きくすると速くなります |

## 注意事項

- J-Quants APIで取得したデータそのものを、閲覧できる形で第三者に配布・共有することは
  規約で禁止されています。分析結果の公開は可能ですが、生データの再配布はできません。
- 本データを用いた投資分析結果を、継続反復して第三者に提供・配信する行為も禁止されています。
- EDINETのAPIにはレート制限があります。`sleep_sec` を短くしすぎないでください。

## データのキャッシュ（差分取得）

一度取得した株価・決算データは `data/` フォルダに自動保存されます（Parquet形式）。

- **初回**: 全期間を取得（時間がかかります）
- **2回目以降**: 保存済みの最終日より後だけ取得 → 数秒〜数分で完了
- 通信量が大幅に減り、毎回の待ち時間もほぼ無くなります

```
data/quotes.parquet   株価日足
data/fin.parquet      決算サマリー
data/listed.parquet   銘柄一覧
```

キャッシュを消したい場合は `data/` フォルダごと削除してください。次回実行時に再取得されます。
古いデータで問題が起きたと感じたときの切り分けにも使えます。
